# 暮らしの条件を判断に反映する修正計画

## 方針

1. 「車なし・子育て・週3通勤」のような普通の条件文から5軸の重みを提案し、画面に見せる。手動調整も残す。
2. 比較を実行するとき、画面で確認した重みをAPIへ渡す。APIの計画・点数・保存レポートを同じ重みにそろえる。
3. 判断理由は地域名、取得できた指標の値・基準年、その条件で何を意味するか、未確認の点を一続きで示す。LLMの説明も同じ根拠に限定する。
4. 駅名などの地域固有情報は、確認できる出典があるときだけ背景情報として載せる。総合点に加算しない。
5. 欠損を好成績として扱わない。警察庁CSVに自治体コードがない場合の事故0件は未取得へ戻す。

## 実装と確認

- 高崎駅の上越・北陸新幹線接続は [JR東日本の高崎駅時刻表](https://timetables.jreast.co.jp/timetable/list0934.html) で確認し、背景情報として添える。駅までの距離、本数、運賃は評価しない。
- 公式公開データで取れない情報は推測せず、本文で未確認事項を明示する。
- 既存の全国スナップショットには警察庁CSVで自治体コードが見つからず「0件」と書かれた行がある。読み込み時に採点対象外とし、次回同期から行自体を作らない。
- 重みの変更、APIへの伝達、地域固有情報が採点に混ざらないこと、欠損の扱いをテストする。
