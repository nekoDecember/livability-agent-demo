# 住む場所の比較 UI

会話履歴ではなく、候補地・評価軸・根拠・実行記録を主役にした専用フロントです。

## 受け入れ条件

- 候補地を都道府県→市区町村から2～4件選び、比較表で横並びに表示できる。
- 移動、住まい、医療・子育て、防災、将来性の5軸を表示できる。
- 評価軸を選ぶと、指標・出典・基準日・信頼度を確認できる。
- 最重視する軸を選べる。評価軸の優先度を変更すると「今選ぶなら」と軸の勝ち数が更新される。
- 比較完了後に、選ぶ街・勝つ軸・受け入れる弱点・次に確認することを表示する。3点未満の差は僅差として勝ち数に含めない。
- 色付きの単体HTMLレポート、Markdown、JSONをダウンロードできる。
- 評価モードを「外部データあり」と「LLM知識だけ」から選べる。
- API接続時は実際の進捗イベントをSSEで表示する。
- APIに接続できない場合は比較を実行せず、接続状態を表示する。
- チャット履歴やAIキャラクターをUIの中心に置かない。

## ローカル起動

APIなしでUIだけ確認する場合:

```sh
npm install
npm run dev
```

ブラウザで <http://localhost:5173> を開きます。APIが利用できない場合は自動的にデモデータへ戻ります。

APIも起動する場合は、別ターミナルでプロジェクトルートから実行します。

```sh
docker compose --env-file .env.backend up --build -d --wait
```

APIキーを設定している場合は、フロントエンドの `.env.local` に設定します。Viteの開発プロキシがサーバー側でBearerヘッダーを付与するため、ブラウザ側へキーを公開しません。

```sh
cp .env.example .env.local
# .env.local の LIVABILITY_API_KEY に同じBearerキーを設定
```

別ホストのAPIへ接続する場合は、`.env.local` の接続先を変更できます。

```sh
LIVABILITY_API_TARGET=http://127.0.0.1:8091

## Composeでフロントも起動する

プロジェクトルートで次を実行すると、APIとNginx配下のフロントを一緒に起動します。

```sh
docker compose --env-file .env.backend up --build -d --wait
```

本番用Composeでは、フロントの`/api/`プロキシが内部APIへBearerキーを付けます。

## 境界

- 現在のUIは開発用の比較面です。候補地の並列評価は同じAPIを複数回呼びます。
- モック表示には、実在地域を題材にした開発用の生成値が含まれます。公式評価ではありません。
- 「LLM知識だけ」は地域データAPI・検索を呼ばない評価です。LLMがOpenAI設定の場合は、LLM APIへの通信は発生します。
- APIキーなしの「LLM知識だけ」は、LLMを呼ばずにオフライン代替を表示します。画面とレポートにその状態を残します。
- サーバーが`DATA_MODE=open_data`の場合は「公式公開データ」と表示し、未取得指標を0点にせず採点対象外として示します。出典と利用条件も根拠欄へ表示します。
- 評価軸の重み変更はブラウザ上の再計算であり、サーバーが保存するレポートは変更しません。
- SSEは `/v1/agent/assessments/stream` を利用します。既存のOpenAI互換エンドポイントは変更していません。
